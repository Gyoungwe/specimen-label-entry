## v3.4 标签纠错基线

v3.4 增加 25 项标签纠错检查；核心脚本合计 74 项，另有 5 项安装、备份和回滚检查。纠错检查使用结构化的合成观测，不代表真实模糊或破损图片识别准确率。

| 新增检查 | 验证内容 |
| --- | --- |
| 补全与溯源 | 同采集事件的清晰参考补全坐标、海拔；原读数、原文和参考定位保持可查 |
| 质量判读输入 | 支持整张标签或逐字段标注；未解决的可疑 OCR 不直接作为正式值 |
| 冲突与私有字段 | 合格参考有差异时留空；不复制其他个体的馆藏号与鉴定信息 |
| 传播隔离 | 补全结果不作为新的清晰参考，也不产生新的匹配锚点 |
| 特殊情况 | 缺日期或整张标签缺失时，使用真实用户确认的采集事件组；未确认时不猜 |
| 规则与空间计算 | 采集方式继续执行本批规则；坐标补全后重新匹配网格 |
| Excel 读回 | 第三张“标签纠错”页保存原读数、填写值、匹配依据与人工栏；来源被修改可检出 |

两个写表后端均接入纠错表。无质量标注的旧批次保持原来的处理行为与两张核对工作表。

同一份两条合成记录已分别用 Python 和 Codex 表格后端写表并读回：每份 128 个主表单元格一致，15 条原生数据验证保留，2 条纠错来源逐格一致。两种后端的纠错页已渲染查看，坐标显示保留 8 位小数；未执行 Microsoft Excel 原生应用打开测试。

## 持续验证

仓库的 GitHub Actions 会在干净的 Linux 环境中运行核心脚本与安装测试，覆盖 Python 3.10、3.12、3.14。实际运行状态以 [Actions](https://github.com/Gyoungwe/specimen-label-entry/actions/workflows/tests.yml) 为准。

开发时运行：

```bash
python -m pip install -r specimen-label-entry/requirements.txt
python install.py --host all --dry-run
python -m unittest discover -s specimen-label-entry/scripts -p 'test_*.py' -v
python -m unittest discover -s tests -v
```

# 中间记录与填写约定

识别后的记录保存为 JSON。下面是结构示例，值仅演示格式，不能当作新批次的观测数据：

```json
{
  "sheet": "biaobenku",
  "sources": {
    "source1": {"name": "标签.pdf", "path": "/absolute/path/标签.pdf", "page_count": 1}
  },
  "records": [{
    "source": "source1",
    "page": 1,
    "visually_checked": true,
    "identification_label_present": false,
    "collection_label_text": "中国，河北省……标签原文",
    "identification_label_text": null,
    "values": {
      "标本号": "IOZ(E)0000001",
      "国家": "中国",
      "省": "河北省",
      "具体地点": "标签上的具体地点",
      "经度": 114.1,
      "纬度": 38.2,
      "海拔": 300,
      "采集日期": "2026-08-01"
    },
    "issues": []
  }]
}
```

- `values` 使用模板列名。未知值用 `null` 或省略，不写“无”、0 或估计值。
- `collection_label_text` 是视觉复核后的采集标签文本；原始 OCR 另存 `ocr_text`，不能通过把 OCR 文本改写为“已确认”来替代看图。
- 模糊或破损标签使用 [标签纠错](label-corrections.md) 的 `label_quality`、`field_quality` 与 `cross_label_reviewed`；完全读不到的原文可为 `null`，必须明确标注采集标签质量。原始可疑读数保存在 `observed_values`，有独立清晰参考才补入 `values`；修复结果逐字段保存来源，不重写原文。编译后“标签纠错”页展示原值、填写值和匹配依据。
- 每页可以有多条标本记录；共享标签只关联到照片中能明确识别的标本。不把同一张照片的多枚实体标本误当作多条编号标签。
- 一图多枚先执行 [原像素分组流程](multi-specimen-photos.md)。桥接记录带 `group_id` 和 `image_provenance`，`图像` 填随批交付的相对 PNG 路径。多张照片分别处理、合并到同一批次时，为各来源分配唯一 `source` 键并同步更新记录；保留全部来源指纹、分组证据与逐图覆盖，不能将所有图误指向第一张照片。
- 任意数量共用一个尺时，计划顶层只声明一次 `shared_scale`；各组本地 `scale` 为 `null`。`expected_groups` 可省略或填写本图实际清单数量，用于漏组检查，不是固定数量限制。默认用透明尺叠加到安全空白处；用桥接器 `--compositions` 将“图像”指向 `带比例尺分组/馆藏号.png`，原像素图、尺的源框、透明蒙版和合成位置留在 `image_provenance` 中。共享尺的复制不等于物理尺度已经校准。
- 日期使用 `YYYY-MM-DD`。经纬度为数值十进制度，分别放在经度/纬度列；N/E 为正，S/W 为负；原始字符串另存。度分秒先检查分、秒范围，再换算，保存原精度。
- 标本号与网格号保持文本，保留大小写、括号和前导零；全角标本号括号可规范成半角，保存原图来源。
- 海拔、日期和坐标的区间不折算成单值。原文放 `interval_observations`，例如 `{"海拔":{"raw_text":"1600–1800 m"}}`；编译后该单值列留空并进入纠错明细，不能用它做参考或借其他标签的单值覆盖。典型海拔/采集日期区间也从标签原文识别；完整原文始终保留。
- 扩裁、原片观察和直接截取的经历存 `review_attempts`，每项记录实际 `stage`、来源/视图、字段与结果；详见 [批次与重试流程](batch-retries.md)。自己的重新观察可更新新版原始转录，补全值不能伪装成独立观察。
- 照片交付时通过 `photo_delivery.py` 复制到 `图像/去掉 IOZ(E) 的馆藏号-1.png`，表格馆藏号不变。`image_provenance.delivery_image` 留复制来源与哈希；内部证据、2× 阅读图和正式交付图分别保存。
- 当前模板“属名”填写拉丁属名；“种名”默认完整双名，避免只剩种加词而失去可读性。作者及年代分列，保留组合作者的括号，例如作者 `(Okamoto)`、年代 `1914`。如新用户指定种加词格式，遵从新规则。
- 外部补充中文名称或分类阶元时，在批次 JSON 的 `supplemental_sources` 中记录字段、URL、定位、核对日期；只补充本记录已有可靠学名的分类链，不能据同批其他记录给无鉴定标签的标本定种。
- 如整批同种由用户明确确认，可在对应记录增加 `identification_evidence`，例如 `{"type":"user_confirmation","statement":"用户明确确认的原话"}`；不能用模型猜测填这个字段。
- 非标本页在 `sources[source].excluded_pages` 中逐页记录 `{"page": 2, "reason": "封面"}`。编译器要求每页有记录或明确排除理由。
- 默认在“备注”记录 PDF 页码及待核对原因；完整原文及字段来源保存在 JSON 与人工核对清单中，不扩展原模板列。

## 网格匹配与复核距离

读取工作簿内具有“编号、顶点1经度/纬度……顶点4经度/纬度”的所有工作表，按编号区分大小写。同编号同多边形合并并保留各来源；同编号不同多边形停止并报告。唯一落入多边形内部才填网格号。边界、多解、坐标缺失、表中未覆盖都留空并列候选或原因。中心点可用于人工诊断，不能作为所属网格的自动替代依据。

“任务核心网格”与“供参考”是来源层次，不能混称。核对清单列出命中表名、行号。如果用户只允许任务核心表，先限制读取范围，再匹配；不能把参考表命中写成核心表命中。

命中时计算以该点纬度为基准的局部平面近似边界距离，单位米；`grid_review_distance_m` 默认 200，可设为 `null` 关闭近边界提醒。这个阈值不是 GPS 误差估计。共享边界和重叠区域仍按原规则留空，不因有距离提示就选择某一侧。县区名单取自所有同编号来源，差异写入核对事项。

## 模板校验与分册

`template_checks.py` 读取模板原生数据验证的全部目标范围，只检查实际受约束的已填单元格。空白观测保持空白；缺失内容通过核对事项单独提示。支持内联选项、静态单元格或命名范围选项、整数/小数范围、日期和文本长度；自定义公式、外部引用及无法解析的表达式列为 `unsupported`，不算通过。它不是完整 Excel 公式引擎。

- `passed`：通过已支持的规则。
- `conflict`：用户固定值与模板约束不同；保持用户值，列出实际值和模板要求。
- `invalid`：其他已填值违反模板规则。
- `unsupported`：规则尚未自动验证，需要人工检查。

`validation_summary` 分别报告四类结果；`validation_checks` 保留字段、单元格、分册和标本号。当前模板“保藏状况”的用户值为“完整”、选项为“1.完整”，这是已知待确认冲突，不自动规范化。

`parts` 根据模板验证范围规划分册。本模板最大 249 条，250 条时规划为 249+1；`audit` 中每条记录保留 `part`、`excel_row`、结构化 `flags` 和人类可读 `issues`。主表不新增列，定位信息与边界距离写入独立核对工作簿。

核对工作簿的人工结果和人工备注初始为空。有标签质量问题时增加“标签纠错”表，并读回核验每条原始读数与来源；无质量标注的旧批次仍保留两张核对工作表。人工修订主表后重新执行验证，不将旧清单视为实时空间计算或最新校验结果。
